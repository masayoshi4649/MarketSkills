# 日本の市場拡大・中長期成長株ランキング

## 目的

市場の拡大と、その市場から各社が利益を得る能力を別々に検証する。短期上昇率や話題性ではなく、一次資料、期間整合した財務、受注・KPI、現在のバリュエーションを基礎に候補を採点し、12か月の入口判断と3～5年の出口条件を示す。

## 必須資料

分析を始める前に、次を読む。

- `references/データ取得・検証規約.md`：取得順、コード接続、鮮度、政策DBの定義、数値不整合の扱い
- `references/採点・売買戦略規約.md`：候補条件、100点採点、過熱度、シナリオ、入口・出口の計算規則

## 状態変更を禁止する

情報取得に必要な読取専用経路だけを使う。

- 市場データ収集では、最初に`datalist`を呼び、その時点で掲載される情報取得データセットだけを使う。`collect`を使う場合も、上流処理がGETのデータセットに限定する。
- ニュース取得ツールでは`list_sources`、`search_articles`、`get_article`だけを使う。
- EDINET DBでは会社検索と`get_*`、`search_*`、`list_*`の参照系だけを使う。
- 政策DBでは`get_*`、`search_*`の参照系だけを使う。
- `/register`、`/unregister`、`/unregister/all`、注文、取消、口座・建玉操作、ウォッチリスト追加・削除、分析保存、通知登録、データ登録・修正依頼を呼ばない。
- MCPの表示に`read_only:false`や`may_register_symbol:true`が残っていても、安全性を推測しない。実装確認済みの情報GET以外は使わない。

## EDINET DB・政策DBの利用優先度を決める

- J-Quantsの一括データ、研究機関記事、ニュース、市場統計でテーマと企業を先に絞り、DB呼出をA～Cの優先度に分ける。固定の件数上限は設けない。
- A（高優先）: 一次確認で市場パイ、企業の取り分、重大リスク、正式順位のいずれかが変わる。EDINETの決算、セグメント、希薄化、会計・統治を優先する。
- B（条件付き）: 予備選別後の上位候補で、詳細財務、受注・KPI、政策の直接性により採点、価格帯、無効化条件が変わり得る。
- C（低優先）: テーマの総当たり探索、既に順位外の候補の詳細、結論を変えない背景補足、確認済みデータの再取得。通常は呼ばない。
- 政策DBは、具体的な政策名と企業・セグメントの関係が先に検出され、政策が主要投資仮説の中核である場合に優先度を上げる。
- batchを優先し、同じ結果を実行内で再利用する。必要な一次確認ができない候補は推測で埋めず参考候補へ移す。
- 各DBの利用優先度、使用・未使用の理由、未確認の影響を回答に表示する。

## 既定条件

ユーザーの指定がなければ、次を使い、回答冒頭に明記する。

- 母集団：東証上場の国内普通株。ETF、ETN、REIT、優先株、外国株、整理銘柄を除く。
- 成長仮説の期間：3～5年
- バリュエーションと入口判断の期間：12か月
- ランキング件数：最大10社。EDINETの一次深掘りは予備選別上位から始め、順位と根拠が安定するまで必要な候補に広げる。
- 流動性条件：直近20営業日の売買代金中央値5,000万円以上
- 新規上場から250営業日未満、財務履歴3年未満、必要データの網羅率80%未満は、正式順位ではなく参考候補に分ける。

## 実行手順

### 1. 利用可能性と基準時点を確定する

1. 市場データ収集の`datalist`を毎回最初に呼び、提供元、データセット、入力項目、説明を確認する。
2. ニュース取得ツールの`list_sources`を毎回呼び、有効状態と直近記事の有無を分けて確認する。
3. 分析時刻、価格時刻、日足対象日、開示日時、ニュース公開時刻・取得時刻を別々に保持する。
4. 休場中は「現在値」ではなく「最終取引日終値」と記す。

### 2. 母集団と候補を作る

1. J-Quantsの銘柄マスターで対象商品と上場状態を確定する。
2. J-Quantsの日足で流動性条件を適用する。直近騰落率や`kabus_ranking`を成長候補の抽出条件にはしない。
3. 市場拡大の仮説を、研究機関記事、政府・業界統計の参照情報、ニュースから広く抽出する。この段階で政策DBを総当たりに呼ばない。
4. J-Quantsの一括財務と銘柄マスターで、関連事業、成長率、収益性、CF、希薄化、流動性から予備候補を作る。
5. 全社横断の一次選別は安価な一括データで行い、候補上限50社から深掘り優先度を付ける。上位からEDINET DBのA・B項目を確認し、順位が不安定な場合は次の候補へ追加確認を広げる。
6. `kabus_ranking`は注目度・過熱度の補助にだけ使い、順位の日付と出来高単位をJ-Quantsで照合する。

### 3. 会社識別子を接続する

表示用コード、J-Quantsコード、EDINETコード、正式社名、法人番号、市場区分、外部ティッカーを1社1レコードにする。略称や社名だけで結合せず、銘柄マスターまたは会社検索で確認する。英数字コードを含め、J-Quants用5桁コードを機械的な末尾0付与だけで生成しない。

### 4. 市場のパイを立証する

市場ごとに、基準年と目標年、金額または需要量、地域、対象製品、名目・実質、出典を揃える。

- 原則として、企業経営陣から独立した一次の定量証拠を1件以上、実需を示す先行・実績指標を1件以上必要とする。
- 政府統計、白書、法定計画、業界団体統計、設備計画、認定・採択の実績を優先する。
- 会社資料のTAM、ニュース見出し、検索抜粋、政策テーマへの文字列一致だけでは市場拡大を立証しない。
- 市場CAGRは、対象と単位が同じ値について`(目標値÷基準値)^(1÷年数)-1`で再計算する。
- 定義が揃わない値は合算せず、別の証拠系列として表示する。

### 5. 企業の取り分と実行力を検証する

J-Quantsの一括財務で予備選別した後、優先度がAまたはBの最終候補だけEDINET DBで次を確認する。全候補に同じ詳細endpointを呼ばない。

- 3～5年の売上、営業利益、EPS、営業CF、投資CF、フリーCF、純有利子負債、発行済株式数
- 関連セグメントの売上、利益、全社に占める比率、地域、主要顧客
- 受注高、受注残、解約、book-to-bill、継続収益、顧客数、単価、稼働率等の業種固有KPI
- 設備能力、増産計画、販売網、認証、知財、切替コストなど取り分を増やす制約または優位性
- 業績予想の達成履歴、下方修正、希薄化、顧客集中、関連当事者、ガバナンス上の懸念

市場規模とセグメント売上の地域・期間・製品定義が一致するときだけ市場シェアを計算する。政策支出、受注残、会社売上、TAMを相互に代用しない。受注残やIR KPIの抽出値は文書ID、ページ、引用元、信頼度を確認し、論理重複を除く。`needs_review`相当の値は採点しない。

### 6. 政策との関係を補助評価する

政策が市場パイまたは企業の取り分の主要論拠である場合だけ、政策DBの優先度をAまたはBとして確認する。各endpointを同じ母集団・同じ金額定義とみなさず、endpoint名、金額基準、母集団、対象期間、単位を証拠台帳に保存する。同じ政策名でも異なるendpoint間の金額を足す、割る、大小比較する、企業売上や利益とみなすことを禁止する。

直接の企業リンク、認定、調達・補助の採択、継続性、関連セグメントとの一致が確認できた場合だけ政策加点を行う。0件は「観測された直接的政策リンクなし」とし、減点も「政策需要がない」という断定もしない。

### 7. 現在値と同一期の利益を揃える

1. 市場が開いていれば、検証済み現物板の最終約定と時刻、`Buy1`、`Sell1`を確認する。板が取得できない、片側、日付不明、休場ならJ-Quantsの最終公式終値へ切り替える。
2. 実績EPS、会社予想EPS、コンセンサスEPSを年度別に分離し、株式分割を調整する。
3. `評価価格÷同じ年度のEPS`でPERを再計算する。保存済みPERを転載しない。
4. 12か月先の評価に使うEPS年度を明記し、価格基準日と決算期のずれを説明する。
5. EPSまたは発行済株式数の重要な不整合を解決できなければ、点の目標株価を止め、EPS×倍率の感応度表だけを出す。

### 8. 採点と過熱度を分離する

`references/採点・売買戦略規約.md`どおり、基礎点95点と政策加点5点を計算する。根拠のない項目を推測で埋めない。データ網羅率と信頼度を併記し、正式順位は網羅率80%以上かつ重要な未解決不整合がない候補に限定する。

短期騰落、移動平均乖離、出来高急増、倍率拡大、イベント集中は0～100の過熱度にだけ反映し、成長点から加点・減点しない。規制、売買停止、片側板、極端なスプレッドは執行ゲートにする。

### 9. 弱気・基本・強気シナリオを作る

各社について12か月と3～5年を分け、弱気・基本・強気の売上、利益率、EPSまたは業種別評価指標、倍率、価格帯、優勢度、カタリスト、無効化条件を示す。履歴による校正がない数値確率を付けず、優勢度を「優勢・同程度・劣勢」と根拠確信度で示す。

通常企業は同一期EPS×PERを中心に、金融はBPS×PBRとROE、赤字成長企業はEV/Salesと黒字化時期等、利益構造に合う方法を使う。異なる手法を混ぜるときは同じ企業価値・株主価値基準へ揃える。

### 10. 入口と中長期の出口を設計する

価格だけでなく、過熱、板・流動性、次の決算、KPI確認を条件にする。入口上限、分割条件、追いかけ禁止条件を示す。出口は段階利確、価格ストップ、投資仮説の破綻、時間切れ、再評価条件を必ず含める。

個人の資産、損失許容度、保有状況が不明なため、断定的な売買命令や数量指定はしない。一般的な分析例として提示する。

## データ不足と失敗時

- データ0件、記事0件、取得失敗、対象外を区別する。
- `enabled=true`でも直近記事0件なら稼働確認済みとみなさない。ニュース0件を「材料なし」と言い換えない。
- 板の`INVALID_ARGUMENT`を銘柄不存在とせず、J-Quantsへフォールバックする。
- `is_stale:null`は新鮮ではなく判定不能とする。
- 異なる情報源の数値差は平均しない。原資料で期、単位、連結範囲、帰属、累計・単期、分割調整を確認する。
- 正規化できない重要数値が残る候補は正式順位から外し、「参考」「算定不能」と理由を示す。
- 低優先のため一次確認を省略し、必要証拠が足りない候補は、推測で網羅率を上げず参考候補に移す。

## 回答形式

出典は各主張の近くに文書ID、開示日、対象期、URL等を付け、最後に証拠台帳を示す。事実、会社計画、外部予測、分析上の推定を明示的に分ける。

EDINET DB・政策DBの利用優先度、使用・未使用の理由、未確認項目と正式順位への影響を分析条件に記載する。

**回答文の作成に着手する直前に、`assets/回答テンプレート.md`を必ず読み直す。既に実行途中で読んでいても再読を省略しない。最終回答は同テンプレートの見出し名、順序、表の列を同じ構造で使用する。該当情報がない欄も削除せず、「未確認」「該当なし」「算定不能」のいずれかと理由を記す。**
