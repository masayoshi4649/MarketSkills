# データ取得・検証規約

## 取得順

1. 市場データ収集の`datalist`で、実行時点の提供元、データセット、入力仕様を確認する。
2. ニュース取得ツールの`list_sources`で、実行時点のソース一覧を確認する。
3. J-Quantsの銘柄マスターで会社識別子と商品区分を確定する。
4. J-Quantsの日足で母集団、対象日、流動性、価格履歴を確定する。
5. 研究機関記事、市場統計、ニュースから市場テーマ候補を抽出する。
6. J-Quantsの一括財務で企業候補を予備選別する。
7. EDINET DBは予備選別上位から、優先度A・Bの財務、決算、セグメント、受注残、KPI、イベント、希薄化を確認する。
8. 政策DBは具体的な政策が主要仮説の中核である場合だけ、優先度A・Bとして直接性を確認する。
9. 最終候補だけ現物板、規制、取引所イベントを再確認する。
10. 回答直前に価格、板、ニュースのうち変化し得る項目を再取得する。EDINET DB・政策DBは訂正の具体的疑いがなければ再取得しない。

現在のデータセット名や入力値を記憶で決めず、毎回`datalist`の返却仕様を正とする。

## ツールの役割

| 情報源 | 主用途 | 強み | 採点上の制約 |
|---|---|---|---|
| 市場データ収集・J-Quants | 銘柄マスター、公式日足、財務速報、決算予定、信用・空売り | 全銘柄横断、対象日付き | 日次・週次でありリアルタイムではない |
| 市場データ収集・KabusController | 現物板、最良気配、規制、銘柄情報、ランキング | 入口時の執行確認 | 日付・単位・市場状態を別途検証。成長点には直結させない |
| 市場データ収集・225225.jp | 市場全体、業種、為替等の補助 | 場中文脈 | 一次の企業財務として使わない |
| EDINET DB | 法定開示、財務、決算、セグメント、受注残、IR KPI、企業イベント | 会社の取り分と収益化の中核 | 抽出・正規化誤差を原文と照合する |
| 政策DB | 政策テーマ、直接企業リンク、認定、調達、補助、白書 | 政策需要と公的資金の経路 | endpointごとに母集団・金額定義が異なる |
| ニュース取得ツール | 直近材料、市場反応、テーマ探索、JPXアラート | 公開後の解釈と更新 | IR・TDnet・決算短信の網羅経路ではない |

## EDINET DB・政策DBの利用優先度

| 優先度 | 判定 | 主な例 |
|---|---|---|
| A（高優先） | 結果で市場パイ、企業の取り分、重大リスク、正式順位が変わる | EDINETの決算・セグメント・希薄化・会計問題、中核政策の直接性 |
| B（条件付き） | 予備選別後の上位候補で、追加確認により採点・価格帯・無効化条件が変わり得る | 詳細財務、受注・KPI、政策の企業リンク |
| C（低優先） | 結論を変えない総当たり探索・背景補足・重複取得 | 政策テーマ全件探索、順位外候補の詳細、確認済み文書の再取得 |

- 固定の呼出件数上限は設けない。必要性が高ければ確認を続ける。
- EDINET DBのA項目を政策DBの背景補足より優先する。
- batchを優先し、同一会社・文書・期間の結果を実行内で再利用する。
- 低優先の未取得を推測で埋めない。必要証拠が不足する候補は参考へ移す。
- 回答に各DBの利用優先度、使用・未使用の理由、未確認の影響を表示する。

## 鮮度の時計

次を別フィールドとして保持し、回答に表示する。

| 時計 | 意味 |
|---|---|
| 分析時刻 | 判断を行った日本時間 |
| `collected_at`・`upstream_fetched` | データを取得した時刻 |
| `CurrentPriceTime` | 最終約定時刻 |
| `Buy1`・`Sell1`の取得時刻 | 板スナップショットの時刻 |
| 日足`Date` | 公式価格の対象取引日 |
| 開示日時・対象期 | 財務数値が公表された時点と経済期間 |
| `published_at` | ニュースの公開時刻 |
| `fetched_at` | ニュースDBへの取得時刻 |

取得時刻が新しくても、対象日や開示対象期まで新しいとは限らない。`is_stale:null`は「新鮮」ではなく「判定不能」、`market_state:unknown`は開場中ではなく「不明」とする。

## コード正規化

1社につき次のキーを保存する。

| キー | 例 | 注意 |
|---|---|---|
| 表示用コード | `194A` | ニュース検索に使う |
| J-Quantsコード | `194A0` | マスター検索で確定する |
| EDINETコード | `E39640` | EDINET会社検索で確定する |
| 正式社名 | 法人格を含む名称 | 略称と区別する |
| 法人番号 | 13桁識別子 | 政策DB接続に優先する |
| 市場区分 | プライム等 | 対象商品を確認する |
| 外部ティッカー | `194A.T`等 | 補助情報だけに使う |

英数字コードを含むため、表示用コードから5桁コードを文字列操作だけで作らない。社名検索が0件でもコード検索を試し、正式名・法人番号・市場区分のうち少なくとも2項目で一致を確認する。

## 市場パイの証拠契約

### 証拠の階層

| 階層 | 例 | 扱い |
|---|---|---|
| A | 政府統計、法定計画、業界団体統計、認定実績、設備能力計画 | 定量採点の中心 |
| B | 企業外の調査機関が出典と期間を示す推計 | 一次出典を追跡できるとき採用 |
| C | 企業資料のTAM・経営目標 | 会社仮説として補助 |
| D | ニュース見出し、検索抜粋、関連記事欄 | テーマ発見だけに使用 |

市場拡大を強く認定する最低条件は、階層Aまたは一次出典を追跡できるBの定量系列1件と、足元の実需を示す別系列1件である。各系列に次を記録する。

- 指標名と値
- 基準年、目標年、予測期間
- 金額・数量・容量の単位
- 地域、製品、顧客範囲
- 名目・実質、総額・純額、予算・執行・受領の別
- 公表日、資料名、URLまたは資料識別子
- 一次事実、会社計画、外部予測、分析推定の区分

系列の定義が一致するときだけCAGRや差分を計算する。政策予算を市場規模、企業の受注、企業売上のいずれにも置き換えない。

## 企業の取り分を示す証拠

市場拡大と企業価値の間を、次の順でつなぐ。

1. 対象市場と開示セグメントの製品・地域・顧客が重なる。
2. 関連セグメントの売上・利益構成比が確認できる。
3. 受注高、受注残、book-to-bill、継続収益、顧客数、単価、設備能力等が市場拡大に連動する。
4. 競争優位または供給制約を解く能力が一次資料で確認できる。
5. 成長が営業利益、営業CF、フリーCF、1株利益へ転換している、または転換計画に検証可能な節目がある。

`市場シェア=セグメント売上÷市場規模`は、期間、通貨、地域、製品範囲、総額・純額が一致した場合だけ計算する。不一致なら「シェア算定不能」とし、受注や顧客獲得等の代理指標を明記する。

受注残は同じセグメント・単位なら`受注残÷直近年商`を受注残カバー率として計算できる。book-to-billは`受注高÷売上高`とし、分母・分子が同じ期間・範囲のときだけ使う。金融、ソフトウェア等で受注残が不適切なら、継続収益、解約率、預かり資産、契約数等の業種固有KPIへ置き換える。

## EDINET DBとJ-Quantsの数値整合

### 証拠台帳

重要数値ごとに次を保存する。

| 項目 | 内容 |
|---|---|
| 指標 | 売上、EPS、発行済株式数等 |
| 値・単位 | 元の表示値と正規化値 |
| 対象期間 | 年度、四半期、累計・単期 |
| 連結範囲・帰属 | 連結・単体、親会社株主帰属等 |
| 情報源 | EDINET文書ID、J-Quants開示ID、URL |
| 公表日 | 公表された日 |
| 調整 | 株式分割、会計基準、通貨換算 |
| 状態 | 一致、丸め差、要確認、未解決 |

四半期の実績が累計値、会社予想が通期値である場合、直接比較して「上振れ」「未達」と呼ばない。前年同期、会社の進捗計画、季節性を使って別途評価する。

### 不整合処理

1. 期間、単位、連結範囲、帰属、累計・単期、株式分割を揃える。
2. 原資料のXBRLまたは法定開示本文を最優先し、EDINET DBの文書IDとページをたどる。
3. `相対差=|A-B|÷max(|A|,|B|)`を計算する。
4. 同一定義で相対差0.1%以下または元表示の1単位以内なら「丸め差」とできる。
5. 0.1%超1%以下は「要確認」、1%超、符号違い、EPS・株式数の期ずれは「未解決」とする。ただし原資料で理由が判明すれば補正内容を記録する。
6. 差のある値を平均しない。原資料で採用値を決められなければ範囲で示す。

EPS、発行済株式数、現在価格、対象市場規模、関連セグメント売上、受注残は重要数値とする。重要数値が未解決なら関連採点を欠測にし、正式順位から外す。目標株価に関係する場合は点推定を停止し、入力値の感応度表だけを出す。

## 現在価格とEPSの期間整合

価格の優先順位は次のとおりとする。

1. 当日セッションと確認できるKabuの最終約定価格・時刻。入口価格には`Buy1`を最良買い、`Sell1`を最良売りとして使う。
2. 最終約定がないが、同時刻の正常な両側板がある場合の板中値。必ず「気配中値」と表示する。
3. J-Quantsの最新公式終値。休場中と板取得不能時の既定値とする。

`AskPrice`・`BidPrice`の名称から向きを推測せず、`Buy1`と`Sell1`を正とする。片側板、逆転板、日付不明、極端なスプレッドは現在価格に採用しない。

EPSは次を別系列にする。

- 直近通期実績EPS
- 対象年度の会社予想EPS
- 対象年度のコンセンサスEPS
- 分析上の弱気・基本・強気EPS

各系列に決算期末、開示日、分割調整を付け、`価格÷同一期EPS`でPERを再計算する。保存済みPERや別年度EPSを現在価格と混ぜない。12か月目標では、原則として12か月後に市場が評価すると考える通期のEPSを使い、年度選択理由を明記する。

### endpoint間で揃わない定義

| endpoint | 金額・母集団の意味 | 禁止する解釈 |
|---|---|---|
| `get_policy_themes` | 主に行政事業レビューの事業名をテーマ一致させたテーマ集計 | 日本全体の市場規模 |
| `get_policy_theme_companies` | テーマに一致した法人とendpoint固有の純額等 | 専業企業一覧、企業売上 |
| `get_policy_theme_funding_scale` | 累積公的資金と直近売上等を並べた規模指標 | 政策が売上を生んだ因果、依存度 |
| `search_policy_company_links` | endpoint固有の接続母集団にある上場企業 | テーマ関連企業の完全一覧 |
| `get_company_policies` | 行政事業レビューの事業単位支出で、支出先から先の再委託を含み得る | 会社の純受領額、受注売上、利益 |
| `get_company_public_funding` | 公共調達・補助金等の採択・受領イベント | `get_company_policies`との合算 |
| `get_policy_budget_reach` | 総予算と企業純額が異なる表・母集団に由来する | 総予算÷企業純額による到達率 |
| `get_policy_funding_path_mix` | endpoint固有の資金経路構成 | 他endpointの総額との増減比較 |
| `get_policy_gap_overview` | 接続・収録の欠損状況 | 政策支出または市場需要そのもの |

同じテーマで会社別金額がテーマ集計を超えて見えても、ただちに矛盾や重複とは判定しない。endpoint名、データ版、期間、母集団、総額・純額、予算・執行・受領、単位がすべて一致する場合だけ比較する。異なるendpoint間の金額は加算、除算、順位付けをしない。

政策DBで0件の場合は「検索条件と収録範囲で直接リンクを観測できなかった」と記す。政策との無関係、市場不存在、需要減少とは判定しない。

## ニュースの使い分け

| ソース群 | 主用途 | 注意 |
|---|---|---|
| Reuters日本・経済 | 場中の市場解釈、マクロ・為替 | 一次の企業財務を置き換えない |
| Yahooカテゴリ | 材料の発見 | 元の一次資料へ遡る |
| ITmedia NEWS | 技術・製品・産業テーマ | 重複、関連記事、共通部の偽陽性を除く |
| 大和総研 | 金利、景気、海外政策の仮説 | 本文のナビ・関連リンクを証拠にしない |
| 日本総研 経済・政策 | 中長期マクロ、制度、市場構造 | 本文が短い場合は証拠に使わない |
| 日本総研 先端技術 | AI、宇宙、自動運転等のテーマ探索 | 概要・目次だけなら定量採点しない |
| JPXマーケットニュース | 上場、監理・整理、上場廃止、指数、値幅イベント | TDnetではない |
| JPX売買停止 | 停止の要確認アラート | 可変本文を過去停止理由の証拠にしない |

記事0件のソースは稼働未確認であり、「材料なし」ではない。企業IR・TDnet・決算短信の網羅性は、優先度A・Bの最終候補だけEDINET DBで一次確認する。

検索は最大5語のAND条件であるため、正式社名、法人格を除いた名称、略称、英文名、表示用コード、全角・半角表記を別クエリにする。J-Quantsの5桁コードをそのままニュース検索へ渡さない。

重複排除は`source_id + external_id`を基本キーとし、同じキーは`updated_at`、`revision_id`、`fetched_at`の新しい改訂を残す。JPXの一覧URLは複数事象を含み得るため、`canonical_url`だけで消さない。同一事象はイベント群にまとめ、一次資料を主、報道を市場解釈とする。

## 状態変更境界

- 市場データ収集は、`datalist`で情報取得と確認でき、上流がGETのデータセットだけを使う。
- `/register`、`/unregister`、`/unregister/all`を呼ばない。
- 注文、取消、口座、建玉、銘柄登録状態を変更しない。
- EDINET DBのウォッチリスト、分析保存・削除、ダッシュボード変更、通知登録・解除、データ修正・追加依頼を呼ばない。
- サーバーURL、APIキー、認証情報を回答やスキルへ記録しない。
