# 東証プライムの復活候補を順位付けする

下落率の大きさではなく、悪材料からの改善経路と急落前後の値動きから復活確度を評価する。事実と推論を分けつつ、最終判断を「買い候補」「条件付き買い候補」「反転待ち」「見送り」のいずれかに確定する。

## 必要な資料を読む

開始時に [references/data-contracts.md](references/data-contracts.md) と [references/scoring-and-gates.md](references/scoring-and-gates.md) を読む。円価格の売買案を作る場合は [references/entry-exit.md](references/entry-exit.md) を読む。回答は [assets/回答テンプレート.md](assets/回答テンプレート.md) の簡潔さと見出し順を基準にする。

## 分析条件

- 対象は東証プライムの普通株に限定する。
- ユーザー指定がなければ下落率上位20銘柄を母集団にする。
- 短期は5～20営業日、中期は1～6カ月とする。
- 復活目標は、悪材料後も妥当性が残る急落前レンジまたは最初の有意な抵抗帯とする。前日終値や年初来高値を自動目標にしない。
- 分析時刻、市場状態、価格の対象日時をJSTの絶対日時で示す。
- 有望5銘柄を目安に深掘りし、追加調査に価値がある場合だけ最大7銘柄まで広げる。最終回答は上位3銘柄を基本とし、基準を満たさなければ穴埋めしない。

## 使用範囲

- 市場データ収集、ニュース取得ツール、公式会社IR、TDnet・JPX適時開示の情報取得だけを使う。
- EDINET DB、政策DB、J-Quantsの`edinet_*`データセットを使わない。
- 通常経路では、上流の銘柄登録状態を変え得る板・規制・銘柄情報の取得を使わない。場中価格は下落率ランキング、売買条件は日足で作る。
- 銘柄登録・解除、注文、取消、口座・建玉操作を行わない。
- 直接サーバーURLやAPIキーをスキルまたは回答へ記載しない。

## 母集団を作る

1. 市場データ収集のデータ一覧を確認し、実行時点で利用できる入力名を使う。
2. 取引中は、KabusControllerのプライム値下がり率ランキングが返した全件をJ-Quants銘柄マスターと突合し、普通株条件を適用してからランキング順の先頭20銘柄を速報母集団にする。対象日が返らないため、J-Quantsまたは225225.jpで日付を照合する。
3. 取引日の大引け後は、J-Quantsの当日分が更新済みなら銘柄マスターと対象日・前営業日の日足から全プライム普通株の騰落率を再計算する。未更新なら、225225.jp等でランキング対象日が当日と照合できた場合だけKabusControllerのランキングを「引け後速報」として使い、前営業日のランキングへ置き換えない。
4. 取引開始前と休場日は、当日ランキングが未形成であることを明記し、J-Quantsの最新公式取引日のランキングを日付付きで示す。
5. 銘柄マスターでは`Mkt=0111`、`ProdCat=011`、5桁コード末尾`0`をすべて満たすものに限定する。名称に「優先株式」がある銘柄も防御的に除外する。
6. 調整終値が両日ともあり、当日出来高が正の銘柄だけを対象にする。分割・併合、調整係数、権利落ちの不整合がある銘柄は候補外にする。

取引中のランキングは「速報」、J-Quants当日分が更新済みの引け後ランキングだけを「確定」と呼ぶ。

## 上位候補を調べる

母集団全件には、Kabu価格とJ-Quantsの直前21本の日足を使い、直前20日売買代金中央値、直前の過熱、当日後刻の決算、売買停止等、急落原因の見出しだけを確認する。単位未確認のKabu出来高・売買代金は計算に使わない。明確な候補外条件を満たした銘柄の詳細調査は止める。

深掘り候補では次を確認する。

1. J-Quantsの調整済み日足を通常60営業日、支持抵抗に必要な場合は最大120営業日まで広げる。
2. 直前5～10営業日の上昇、急落後の位置、ATR20、支持抵抗、TOPIX・33業種に対する相対下落を計算する。出来高・売買代金倍率はJ-Quantsの当日分が更新済みの場合だけ計算し、取引中は未算定でも減点しない。
3. J-Quantsの財務サマリーで最新業績、会社予想、予想変更、EPS、CF、財務余力を確認する。CF等が最新行で空なら、最新の非空行を対象期間付きで使う。決算予定は全決算期を対象に取得できる経路を優先する。
4. 会社固有の急落では、会社公式IRまたはTDnet・JPX適時開示の原文を深掘り候補で確認する。決算短信、説明資料、業績修正、増資、自社株、M&A等を優先する。
5. ニュース取得ツールはReutersを市場解釈、JPXマーケットニュースとJPX株式売買停止情報を制度イベントの確認に使う。ニュース0件を「材料なし」と解釈しない。
6. 信用残と空売りは基準日付きの補助材料に限り、欠損だけで順位を止めない。

## 急落原因を分類する

- **一時的・測定可能**: 計上時期、検収遅延、一過性費用、障害等。回収時期と確認指標があれば高評価にする。
- **期待値調整**: 好決算でも上方修正なし、材料出尽くし、直前急騰の反動、地合い・業種売り。業績が維持され過熱が解消した場合は候補にする。
- **循環的**: 需要循環、在庫調整、顧客投資の減速。受注、在庫、稼働率等の改善指標がある場合だけ評価する。
- **構造的**: 競争力低下、継続赤字、財務悪化、会計・統治問題、大幅希薄化。具体的な改善策と期限がなければ見送る。

原因を一つの短い因果関係にまとめ、確認済み事実と推論を混ぜない。

## 一つの点数で順位付けする

[references/scoring-and-gates.md](references/scoring-and-gates.md) に従い、復活確度点0～100だけを算定する。点数は順位用であり確率ではない。

- 未確認の好材料には加点しない。
- 補助データの欠損を理由に分析全体を止めず、確認済み情報だけで保守的に評価する。
- 最低条件を欠く銘柄は候補外にし、次順位を調べる。
- 同じ悪材料を複数項目で重複減点しない。
- 総合点から短期・中期のA～Dを導き、それぞれ一段階まで調整する。別の100点を作らない。
- 同点は、悪材料の改善可視性、業績の裏付け、20日売買代金中央値の順で決める。

## 売買判断を確定する

- **買い候補**: 復活確度点65以上で、日足の反転トリガーが発動し、最初の抵抗まで1.5R以上あり、5営業日以内に公表済みの重要イベントがない。
- **条件付き買い候補**: 復活確度点65以上で、急落日OHLCから仮エントリーを置いたR/Rが1.5以上、5営業日以内に公表済み重要イベントがないが、反転トリガーは未発動。将来の入口条件を示し、発動前に実際の確認日高値でR/Rを再計算する。
- **反転待ち**: 復活確度点65以上だが、取引中で急落日OHLC未確定、R/R未確認、または5営業日以内の公表済み重要イベントの通過待ち。
- **見送り**: 復活根拠が弱い、構造悪化、流動性不足、価格データ不整合、またはR/R不足。

状態が重なる場合は、見送り条件、5営業日以内の公表済み重要イベント待ち、OHLC・R/R確認待ち、条件付き買い候補、買い候補の順に判定する。

入口が発動した銘柄がなければ「今すぐの買い候補なし」と明記したうえで、条件付き買い候補の有無を続ける。データ欠損の説明で結論を曖昧にしない。

## 回答を作る

ユーザーが詳細を求めない限り、回答は原則2,500字以内に収める。

1. 冒頭2～3文で、1位、短期・中期の最有力、今の売買判断を示す。
2. 上位3銘柄を、急落原因、改善経路、復活確度点、短期・中期評価、売買判断とともに一つの表へまとめる。
3. 売買案は買い候補、条件付き買い候補、復活確度点65以上の反転待ちを対象に最大3銘柄まで作る。急落日OHLCが確定済みなら、入口、損切り、第1・第2利確、時間切れ、無効化条件を円価格で示す。取引中で当日高安が未取得なら、架空の円価格を作らず、大引け後に数値化する反転条件と再評価時刻を示す。
4. 主な候補外は最大3銘柄を一行理由で示す。
5. 価格日、財務開示日、遅行データの基準日を区別し、会社資料と主要データへ直接リンクする。

内部の取得件数や停止ログ、複数の点数、点数幅を回答へ出さない。
上位表の急落原因と根拠は各銘柄1～2文に収め、同じ根拠を表の後で繰り返さない。根拠リンクで回答を終え、実行メモや利用ツール一覧を追記しない。

## 品質確認

- プライム普通株の条件をすべて適用したか。
- 下落上位20を確認し、知名度だけで選んでいないか。
- 当日下落と直前急騰の吐き出しを区別したか。
- 原因、改善期限、観測指標の少なくとも一つを確認したか。
- 点数、短期・中期評価、売買判断が同じ根拠から一貫しているか。
- 結論が冒頭にあり、「買い候補」「条件付き買い候補」「反転待ち」「見送り」のいずれかを明示したか。
- 急落日OHLCが確定済みの場合、円価格の入口、損切り、利確、時間切れ、無効化条件が整合しているか。未確定なら円価格を作らず再評価時刻を示したか。
