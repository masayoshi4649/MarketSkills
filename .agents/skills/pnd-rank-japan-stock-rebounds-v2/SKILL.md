# 日本株の復活候補と出口戦略を順位付けする

下落率の大きさを割安さとみなさず、「急落前の妥当な価格帯へ戻る根拠」と「現在から取引を成立させられるか」を別々に評価する。点数は順位用の指数であり、確率ではない。

## 必須資料を読む

開始時に [references/data-contracts.md](references/data-contracts.md) と [references/scoring-and-gates.md](references/scoring-and-gates.md) を読む。価格案の作成前に [references/entry-exit.md](references/entry-exit.md) を読む。

**回答文の作成直前に [assets/回答テンプレート.md](assets/回答テンプレート.md) を必ず完全に読み直す。最終回答は同じ見出し順、表の列、状態区分を使う。未取得項目や候補0件でも構造を削らず、理由と再評価条件を記す。プレースホルダーを残さない。**

## 状態変更を禁止する

- 市場データ収集、ニュース取得ツール、EDINET DB、政策DBの情報GETだけを使う。
- `/register`、`/unregister`、`/unregister/all`、注文、取消、口座・建玉操作を呼ばない。
- 直接サーバーURLやAPIキーをスキルまたは回答へ記載しない。

## 1. 実行条件を固定する

1. 分析時刻をJSTの絶対日時で記録し、取引中・大引け後・休場を判定する。
2. ユーザー指定がなければ、取引中は取得できた速報下落全件、大引け後は全普通株から下落率上位30または下落率-5%以下の最大50件を母集団とする。
3. 短期を最大20営業日、中期を最大60営業日とする。
4. 復活を、悪材料を織り込む前の妥当な支持・評価帯への条件付き回帰と定義する。前日終値や年初来高値を自動目標にしない。
5. 深掘りを既定8銘柄、絶対上限10銘柄に限る。同点でも10銘柄を超えず、売買代金とデータ鮮度で絞る。有効候補が8未満なら穴埋めしない。
6. EDINET DBと政策DBの利用前にmateriality gateを通し、A（最終判断に必須）、B（候補間順位を変え得る）、C（背景補足または早期除外後）の優先度を付ける。Cは呼ばず、AのEDINET一次確認を政策DBより優先する。
7. EDINET DBはバッチを優先し、同一結果を再利用する。政策DBは最終候補の投資仮説の中核に、直近・重要・直接的な政策が必要な場合だけ使う。
8. raw候補数、普通株数、標準レーン数、早期除外数、観測・保留数、深掘り数、最終順位数を記録する。

## 2. 母集団を作る

1. 毎回、市場データ収集のデータ一覧を確認する。
2. `kabus_ranking`と225225.jpの下落ランキングを速報候補にする。返却件数や対象日を推測しない。
3. 大引け後はJ-Quantsの当日・前営業日の日足と銘柄マスターから騰落率を再計算する。
4. 上場中の普通株`ProductCat=011`に限定し、当日・前日終値、出来高、売買代金が非nullで当日出来高が正の銘柄だけを本母集団にする。
5. 調整終値を使い、`ExRT`、`AdjFactor`変化、分割・併合があれば原本確認まで保留する。nullを0へ変換しない。
6. 4桁・英数字表示コード、J-Quants 5桁コード、EDINETコード、正式社名をコードで接続する。

取引中は速報母集団と明記し、ランキング・現在値の取得が5分を超えたら再取得する。大引け後はJ-Quantsの`Date`が当日でなければ確定ランキングと呼ばない。

## 3. 安価な選別ファネルを順守する

全候補に同じ詳細調査を行ってはならない。次の段階を順番に実行する。

1. **一括スクリーニング**: 市場データ、銘柄マスター、JPXの共通一覧、ニュース見出しの一括結果だけで、種類、上場状態、価格、流動性、時価総額、値幅制限、企業行動、既知の重大イベントを検査する。
2. **ゲート**: [references/scoring-and-gates.md](references/scoring-and-gates.md) のハード除外、観測、保留、早期除外を適用する。十分な除外材料を確認した時点でその銘柄の追加取得を停止する。
3. **深掘り優先度**: 通過候補を、原因候補の明確さ、流動性、相対下落と過熱解消、時間軸内の観測機会、データ鮮度で並べる。これは調査順であり投資点数ではない。
4. **限定深掘り**: 上位8銘柄だけを詳細調査し、追加候補に十分な価値がある場合のみ10銘柄まで拡張する。

標準売買レーンは株価100円以上、直前20日売買代金中央値1億円以上、時価総額50億円以上、履歴20営業日以上とする。未達銘柄は観測レーンへ移し、具体的な売買案を出さない。値幅下限、一方向板、IPO後60営業日未満、分割調整不整合は保留とする。

閾値は既定値であり、将来のwalk-forward検証で調整する。各段階の処理件数、状態、理由コード、取得停止を決めた最小限の根拠を保持する。全件の詳細調査は監査性の要件ではない。

## 4. 急落原因を一次情報で確認する

深掘り対象だけを次の順で調べる。各手順の後に早期除外条件を再評価し、成立したら後続手順を停止する。

1. 市場データ、JPXイベント、ニュース見出しで原因仮説を作り、EDINETが本当に必要かmateriality gateを通す。
2. EDINET DBは原因の一次確認、格付けの必須入力、または価格目標の無効化条件を決める場合に限る。コード解決、決算、イベント、決算予定はバッチ取得を優先する。
3. 希薄化、業績修正、決算、会計・統治、M&A、自社株等をタイトルと必要最小限の原本で再分類する。自動`severity`だけで判断しない。
4. ここまで通過した候補だけ、財務、セグメント、受注残、KPI、IR文書を取得する。
5. ニュース取得ツールのソース健全性は1度だけ確認する。銘柄別詳細検索は深掘り対象に限り、正式名、略称、英名、表示コードを別クエリにする。
6. ニュースは原因仮説と市場解釈に使い、公式開示で確認する。ニュース0件は「原因未確認」であって「材料なし」ではない。
7. 政策DBは、最終候補で、直近・直接・重要かつ一次資料と事業の一致が投資仮説の中核になるときだけmateriality gate後に呼ぶ。

EDINETと政策DBはAを先に取得し、Bは安価な情報で未解決の場合だけ取得する。Cは取得しない。必要な一次確認を省略した場合は、該当銘柄を保留または算定不能とし、推測で埋めない。利用した目的・優先度・バッチ再利用と、省略が順位・格付け・出口に与える影響を記録する。

原因の一次確認ができない銘柄は採点保留にする。原因を確認できても、各スコアの必須入力が欠ける場合は点数を作らず「算定不能」とし、根拠がある項目だけを部分点として総合点へ見せない。ニュース重複は`source_id + external_id`を基本キーに最新版を残し、異ソースの同じ事象は一つのイベント群として数える。

## 5. 数値を整合させる

- 深掘り対象だけに、価格・出来高履歴を最低60営業日、支持抵抗に必要な場合のみ120営業日取得する。
- ATR20、出来高・売買代金の20日中央値倍率、急落前5～10日の上昇、相対下落を計算する。
- 現在値と同じ評価期間のEPSからPERを再計算し、保存済み倍率を現在倍率として使わない。
- EDINETとJ-Quantsの売上・利益・EPSを期間、単位、連結範囲、株式数で検算する。不一致を平均しない。
- 信用残は週次、報告空売りは主体別最新行、業種空売り比率は業種指標として扱う。

主要価格が二源で0.5%以上不一致、対象日不一致、訂正開示あり、EPS等の重要不整合が未解決なら、再取得後も解消するまで点目標を停止する。

## 6. 二軸で順位付けする

[references/scoring-and-gates.md](references/scoring-and-gates.md) に従い、次を別々に採点する。

- 復活根拠指数0～100: 原因の修復可能性、業績耐久性、財務・資本政策、期限付き触媒、評価余地、過熱解消、相対下落の説明力。
- 売買成立指数0～100: 反転確認、目標までのR/R、流動性、イベントギャップ、信用・空売り混雑。

さらに、短期復活スコアと中期復活スコアを別々に0～100で算定し、S/A/B/Cへ変換する。短期は反転・R/R・流動性・20営業日内触媒を重く、中期は業績耐久性・修復KPI・財務・60営業日内触媒を重くする。閾値、S上限条件、必須入力は同リファレンスに従う。

復活順位は復活根拠指数で決め、同点は根拠確信度、次に売買成立指数を使う。短期・中期格付けは時間軸別の要約であり、復活根拠指数による順位を置き換えない。各曖昧項目をmin/base/maxで採点し、`72 [66–78]`のように幅を示す。ただし必要証拠が揃っていない項目を推測して幅へ変換しない。幅が重なる銘柄は同一tierとする。必要入力を満たして算定した売買成立指数が60未満なら「監視」とし、短期格付けはCを上限とし、入口案を出さない。

最終ランキングの各銘柄に短期復活格付けと中期復活格付けの両方を必ず付ける。どちらかが必須入力欠損で算定不能な銘柄は最終ランキングに含めず、保留・観測レーンで不足入力と再評価条件を示す。

## 7. 条件付き入口と具体的出口を作る

[references/entry-exit.md](references/entry-exit.md) に従う。急落当日の成行逆張りを既定にせず、反転確認または支持帯再テスト後の条件付き入口とする。

各売買候補で円価格の次を示す。

- エントリートリガーと想定約定帯
- 損切り、予定損失率、1R
- 第1利確、第2利確、残りの追随
- 現在値基準と想定約定値基準の上昇率
- 想定R/R、時間切れの絶対日付、決算跨ぎ方針
- 価格とファンダメンタルズの無効化条件

最初の抵抗帯まで1.5R未満、損失幅が1.5ATRまたは10%超、分足等の必要データ未取得なら、無理に数値案を作らない。損切り価格での約定は保証されず、ギャップで損失が拡大し得ると明記する。

## 8. 回答を検査する

- 安価な一括選別を全候補に適用し、同じフル調査を行わず、十分な除外材料で取得を停止したか。
- rawから最終順位までの件数が整合し、早期除外の理由集計と簡潔ログを残したか。
- 深掘りが既定8、絶対上限10銘柄の範囲か。
- EDINETと政策DBの利用をA/B/Cで事前分類し、Cを呼ばず、AのEDINET一次確認を優先したか。
- 両DBの利用判断、優先度、バッチ再利用、省略影響を示したか。
- 現在値、価格日、取得時刻、遅行データ基準日を分けたか。
- 原因をEDINET・会社原本で確認したか。
- 復活根拠と今取引できるかを分離したか。
- 最終ランキング全銘柄に短期・中期のS/A/B/C格付けがあり、別スコアとS上限条件を守ったか。
- 点数を確率として表現していないか。
- 円価格の入口、損切り、分割利確、時間切れ、決算跨ぎを示したか。
- 事実、推論、未取得、直接リンクを区別したか。
- 回答直前に回答テンプレートを再読し、同じ構造を使ったか。
