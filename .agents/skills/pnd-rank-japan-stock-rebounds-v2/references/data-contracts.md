## 1. 母集団

取引中はKabuまたは225225.jpの速報ランキングが返した全件を「暫定母集団」とする。返却上限を全市場と誤認しない。大引け後はJ-Quants全銘柄から次を満たす銘柄を抽出する。

- 上場中
- `ProductCat=011`の普通株
- 対象日と前営業日の調整終値が非null
- 当日の出来高・売買代金が非nullかつ出来高が正

騰落率を`当日調整終値 / 前日調整終値 - 1`で再計算する。ETF、ETN、REIT等を混ぜない。無商いのnullを0にしない。権利落ち、分割・併合、調整係数変化は原本確認まで保留する。

母集団全件へ行うのは、一括または共通取得で完結する安価なスクリーニングだけとする。銘柄別の一次文書、詳細財務、セグメント、ニュース全文、政策接点の総当たりを行わない。各段階の件数、理由コード、停止根拠を保持する。

## 2. 時刻

| フィールド | 意味 | 禁止する解釈 |
|---|---|---|
| 分析時刻 | 回答作成時刻 | 全データの時点 |
| `collected_at`・`upstream_fetched` | 取得時刻 | 価格の取引時刻 |
| `CurrentPriceTime` | 最終約定時刻 | 板取得時刻 |
| 日足`Date` | 公式取引日 | 夜間の現在値 |
| 信用基準日 | 週次 | 当日リアルタイム需給 |
| 空売り`CalcDate`・`DiscDate` | 計算日・公表日 | 全主体の同時点残高 |
| `published_at` | 記事公開時刻 | ツールが利用可能になった時刻 |
| `fetched_at` | 記事取得時刻 | 公開時刻 |

取引中のランキング・現在板は5分超で再取得する。大引け後は同日終値を再取得する。分析後に現在値が2%または0.5ATR以上動けば、すべての円価格案を失効させる。

## 3. 市場データ

`kabus_ranking`は速報候補、225225.jpは速報照合、J-Quantsは大引け後の母集団確定と日次履歴に使う。Kabuランキングに日付がない場合はJ-Quantsまたは225225.jpで対象日を照合する。表示単位が不明な出来高、売買代金、発行株数を計算に使わない。市場データは銘柄ごとの小分け取得より、同日・同定義の一括取得を優先する。

母集団ではゲートに必要な最小期間だけを一括取得する。60営業日以上のOHLC、支持抵抗用の長期履歴、詳細な信用残・空売り報告は深掘り対象だけに取得する。信用残、空売り報告、業種空売り比率は意味と基準日を分ける。

板は`Buy1`を最良買い、`Sell1`を最良売りとして使う。トップレベルの`AskPrice`・`BidPrice`は一般的な向きと逆である。板取得不能は銘柄不存在を意味しないため、J-Quantsへフォールバックする。

## 4. EDINET DB

1. 安価な市場データ、JPXイベント、ニュース見出しで早期除外と深掘り優先順位を決める。
2. 深掘り対象に限り、利用目的をA/B/Cで事前分類する。Cは呼ばない。
3. コード解決、決算、イベント、決算予定はバッチ取得を優先し、同じ結果を実行中に再利用する。
4. 最終候補の急落原因、希薄化、業績修正、決算、会計問題、M&A、自社株等の優先度Aの一次確認を政策DBより先に行う。
5. 詳細財務、セグメント、受注残、KPI、IR文書は、結果が候補間順位を変え得る優先度Bの場合だけ追加する。

単一エンドポイントの空を「開示なし」とみなさない。決算、イベント、IR文書の収録範囲が異なる。自動`severity`は検索補助であり、希薄化等をタイトルと原文から再分類する。AI抽出、四半期差分、LLM抽出は`sourceType`、`derivationMethod`、`confidence`を表示する。

## 5. ニュース

毎回ソース一覧と直近記事を見て稼働状況を確認する。`enabled=true`でも記事0件なら稼働未確認である。

ソース一覧と市場全体の稼働確認は1度だけ行う。原因見出しの一括結果を早期選別に使い、銘柄別全文検索は深掘り対象に限る。早期除外後の銘柄の追加検索を行わない。

検索は最大5語ANDのため、正式名、株式会社除去名、略称、英名、表示コードを別クエリにする。一般語と衝突する社名は、見出しに会社固有語・コードがあるか、局所本文で社名とコードの双方が一致するものだけ採用する。

重複排除は`source_id + external_id`を基本に、同一キーの最新改訂を残す。`canonical_url`だけで排除しない。JPX一覧ページは異なるイベントが同じURLを共有し得る。異ソースの同じ事象は一つのイベント群へ束ね、JPX・会社開示を事実、Reuters等を市場文脈として保持する。

JPXマーケットニュースは停止、監理・整理、上場廃止、値幅制限等の早期ゲートに使う。可変の停止一覧本文を過去事実の最終根拠にしない。会社IR・TDnetの網羅経路ではない。

## 6. 政策DB

政策DBは、最終候補の投資仮説の中核となる優先度Aまたは、候補間順位が変わり得る優先度Bだけに使う。直近かつ会社へ直接結び付き、売上・利益に重要で、会社資料でも対象事業を確認できる場合だけ補助点にする。早期除外済み銘柄、背景補足、政策テーマ総当たりに使わない。次を合算しない。

- プロジェクトグロスと企業受領額
- 会社政策額とaward型公的資金
- 子会社経由と親会社直接受領
- 同名テーマの異なるエンドポイント集計

エンドポイント名、`amount_basis`、年度・期間、原典を保持する。古い・少額・単なるテーマ所属は0点とし、該当なしを減点しない。

EDINETと政策DBは、利用目的、A/B/Cの優先度、バッチ・再利用、取得後の判断変化、省略影響を記録する。優先度Aを取得できず結論が変わり得る場合は、格付けや目標を推測で埋めず保留とする。

## 7. コードと数値整合

Kabuの省略名を会社検索の主キーにしない。表示コード、J-Quants 5桁コード、EDINETコード、正式社名、法人番号、市場区分をマスターで接続する。5桁コードを機械的な末尾0付与だけで作らない。

現在値と同じ評価期間のEPSからPERを再計算する。保存済みPERを現在倍率と呼ばない。EDINETとJ-Quantsの売上、利益、EPSは単位、累計・単独、連結範囲、株式数を揃え、算術検算する。差を平均しない。未解決なら価格目標を停止し、感応度レンジだけを示す。
