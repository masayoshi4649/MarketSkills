# 判定、NT枚数、出口の計算規則

## 0. 回答表示順と結論表の表記

回答は次の順序で表示する。

1. 結論
2. 売買設計
3. ファンダメンタルズ判断
4. 現在時点の価格アンカー
5. 現在値からのシナリオ予測
6. OP・需給の検証
7. データ鮮度と欠損
8. 無効化条件と再評価
9. 根拠資料

結論表では次を守る。

- 「判断」には`ロング`、`ショート`、`NTロング`、`NTショート`、`見送り`、`保留`のいずれか一語だけを書く。
- 判断理由、データ欠損、イベント注意、サイズ注意は「留意事項」に書く。
- 旧来の入口列を廃止し、入口・出口・撤退を独立させる。
- セルは`入口:4211.5`、`出口:4248.5`、`撤退:4200`のように接頭辞付きで書く。該当しない場合も`入口:該当なし`の形式を保つ。
- 確信度は`60%`のような5%刻みの数値で書き、格付け語へ置換しない。

## 1. 現在値アンカー

有効な両側板について次を計算する。

```text
現在値アンカー = (Buy1.Price + Sell1.Price) / 2
スプレッド     = Sell1.Price - Buy1.Price
```

- 予測価格と予測騰落率は現在値アンカーから計算する。
- ロング入口は`Sell1.Price`、ショート入口は`Buy1.Price`とする。
- 前日終値は「ここまでに何％動いたか」の説明だけに使い、予測騰落率の分母にしない。
- 回答直前に板を再取得したら、アンカー、入口、NT倍率、枚数、出口をすべて再計算する。

NT倍率は同一時点・同一限月の中値で計算する。

```text
NT_mid = 日経225先物の中値 / TOPIX先物の中値
```

執行側の入口倍率も併記する。

```text
NTロング入口   = 日経Sell1 / TOPIX Buy1
NTショート入口 = 日経Buy1 / TOPIX Sell1
```

## 2. 現在判断の有効期限

分析時刻、最終板のスナップショット時刻、有効期限、イベント時刻はすべて`YYYY-MM-DD HH:mm:ss JST`で表示する。

### 基準期限

次から最も早い時刻を基準期限とする。

1. 日中またはナイトの先物取引中は、回答直前の最終板スナップショットから30分後
2. 取引中セッションの終了時刻
3. 先物休場中は、次の取引可能セッション開始時刻
4. データ提供側が明示した失効時刻

板が急変している、スプレッドが拡大している、または取得に時間を要した場合は30分より短くする。基準期限を単に「次のセッションまで」と書かず、必ず絶対日時へ変換する。

### イベントによる短縮

経済指標、日銀・FOMC等の中央銀行イベント、SQ・ロール・セッション境界、指数リバランス、主要構成銘柄の決算、政策公表について、次の既知時刻を洗い出す。

```text
イベント期限 = イベント予定時刻 - 安全余裕
現在判断の有効期限 = min(基準期限, すべてのイベント期限)
```

- 通常の時刻確定済み指標・決算は5分を標準安全余裕とする。
- 中央銀行決定、SQ、時刻幅のある公表、または指数へ非線形な影響が見込まれるイベントは15分以上を使う。
- 安全余裕はイベントごとに明示する。市場慣行や配信遅延により長くした場合は理由を書く。
- 日付だけ判明して時刻が不明な重要イベントは、想定される最も早い公表時刻より前へ期限を置く。安全な時刻を決められなければ判断を`保留`とする。
- すでに安全余裕内なら新規売買を`保留`とし、イベント予定時刻を有効期限、イベント後の板再取得を再評価条件とする。

結論には、現在判断の有効期限、期限設定根拠、直近重要イベントの絶対JST、安全余裕、イベント後の再評価条件を必ず表示する。価格が入口・出口・撤退へ到達した場合、板が失効した場合、イベント予定が変更された場合も期限前に再評価する。

## 3. ファンダメンタルズ・スコア

日経225とTOPIXを別々に、-100から+100で採点する。0は中立または確認不能であり、データ欠損を都合よく正負へ寄せない。

| 要素 | 上限 | 主な証拠 |
|---|---:|---|
| マクロ・金融環境 | ±25 | 金利、為替、海外景気、中央銀行、商品価格 |
| 主要構成銘柄の業績・改定 | ±25 | EDINET一次開示、J-Quants財務、寄与度・ウェイト |
| 政策・制度・地政学 | ±15 | 政策DBの直接材料、公式イベント |
| 投資主体・信用・空売り | ±15 | J-Quantsの対象日付き日次・週次データ |
| 業種の広がり・指数構成 | ±10 | 33業種、騰落、日経寄与度、集中度 |
| ライブ市場・OP確認 | ±10 | 先物板、NT、検証済みOP板・ボラティリティ |

同じ事実を複数ソースで確認しても一度だけ採点する。ニュースは原則として事実の発見と市場解釈に使い、一次資料と二重加点しない。

```text
S_NK    = 日経225の合計点
S_TOPIX = TOPIXの合計点
S_NT    = clamp(S_NK - S_TOPIX, -100, 100)
```

スコアは説明用であり、勝率や騰落率ではない。価格レンジへ機械変換しない。

## 4. 方向判定

### 単純方向

| 条件 | 基本判定 |
|---|---|
| スコアが+25以上、基本シナリオが現在値より上、コスト控除後も余地あり | ロング候補 |
| スコアが-25以下、基本シナリオが現在値より下、コスト控除後も余地あり | ショート候補 |
| -24～+24、証拠が相反、または実行ゲート不合格 | 見送り |

### NT

| 条件 | 基本判定 |
|---|---|
| `S_NT >= +20`かつ日経225の相対リターンがノイズ・コスト帯を上回る | NTロング |
| `S_NT <= -20`かつTOPIXの相対リターンがノイズ・コスト帯を上回る | NTショート |
| -19～+19、相対差がコスト帯内、または両脚ゲート不合格 | 見送り |

閾値だけで自動決定しない。最低でも独立した2カテゴリの根拠を要求し、次を使い分ける。

- 両指数が同方向で広がりもある: 単純方向を優先する。
- 共通方向が不明で相対差だけが明確: NTを優先する。
- 円安・輸出株集中、値がさ寄与、半導体業績が日経を相対的に押す: NTロング側の候補要因。
- 国内金利上昇、銀行・内需の広がり、値がさ株の相対悪化がTOPIXを押す: NTショート側の候補要因。
- 上記は固定則ではない。すでに現在値へ織り込まれた度合いと反証を必ず確認する。

## 5. シナリオ価格帯

ユーザー指定がなければ、次のセッション終了、5営業日、20営業日を示す。弱気・基本・強気の価格帯は、次のいずれかの検証可能な方法で作る。

1. 同一基準日の指数日足から求めた過去リターンの経験分位
2. 有効なATM Call・Put板と残存期間から求めた期待変動幅
3. 決算・政策・指数イベントの明示的な感応度

複数手法を使う場合は前提を示す。根拠がない点の価格目標を作らず、方向と広いレンジにとどめる。価格は対象商品の呼値へ丸める。

```text
現在値比 = (予測価格 / 現在値アンカー - 1) × 100
```

NTは価格だけでなく、`NT_mid`からの倍率レンジまたは相対リターン差で示す。過去日次を使う場合は日経225とTOPIXの日付を完全に揃える。

## 6. 商品乗数

実行時にJPX公式仕様または市場データ契約で再確認する。既定の検算値は次のとおり。

| 商品 | 乗数 |
|---|---:|
| 日経225 mini | 指数×100円 |
| 日経225 micro | 指数×10円 |
| TOPIX mini | 指数×1,000円 |

`TradingUnit=1`は契約枚数単位であり、指数乗数ではない。APIの1注文上限、登録容量、証拠金を混同しない。

## 7. NTの整数枚数

戦略方向に対応する実際の入口気配を`P_N`、`P_T`、各乗数を`M_N`、`M_T`、枚数を`q_N`、`q_T`とする。

```text
日経脚名目 = q_N × M_N × P_N
TOPIX脚名目 = q_T × M_T × P_T
名目差率 = abs(日経脚名目 - TOPIX脚名目)
           / ((日経脚名目 + TOPIX脚名目) / 2)
```

次の手順で日経225 mini案とmicro案を別々に計算する。

1. TOPIX miniを1枚から順に増やす。
2. `q_N = round((q_T × 1000 × P_T) / (M_N × P_N))`を候補にする。
3. 0枚、板数量不足、異常スプレッドの候補を除く。
4. 名目差率3%以下を満たす最小グロス名目の組を選ぶ。
5. 3%以下がなければ5%まで許容して警告する。5%超しかなければ名目中立の具体案を出さない。
6. mini案とmicro案の両方を表示し、スプレッド、板数量、最小グロス名目から推奨案を一つ選ぶ。

証拠金、口座資産、最大損失が未指定なら最小構成を超えて拡大しない。「名目中立に近い枚数」であって「リスク中立」や「安全な枚数」ではない。必要に応じ、日次リターンの回帰βを補助表示できるが、遅行推計と明記し、ライブ名目枚数を隠さない。

### 非リアルタイムの計算例

日経225が69,350、TOPIXが4,212.5だった監査時点の概算では、次が名目差約1.2%の組み合わせになった。

```text
日経225 micro 6枚 : TOPIX mini 1枚
日経225 mini  3枚 : TOPIX mini 5枚
```

これは説明用の過去値であり、固定比率ではない。実行時の執行側価格と板数量で必ず再計算する。

## 8. 入口・出口・撤退

### 単純方向

- ロング: 現在の`Sell1`を入口、決済時の`Buy1`を出口評価に使う。
- ショート: 現在の`Buy1`を入口、決済時の`Sell1`を出口評価に使う。
- 第一目標、第二目標、損切りを現在アンカーと予測レンジから置く。
- 予測期間の終了を時間撤退とし、重要イベント、為替、金利、業績前提の反転を材料撤退にする。
- 結論表では第一・第二目標を`出口:第一...／第二...`、価格損切りを`撤退:...`と要約し、時間・材料撤退は留意事項と第2章「売買設計」で具体化する。

### NTロング

```text
開始: 日経をSell1で買い、TOPIXをBuy1で売る
終了: 日経をBuy1で売り、TOPIXをSell1で買い戻す
損益 = q_N×M_N×(N_exit_buy1 - N_entry_sell1)
     + q_T×M_T×(T_entry_buy1 - T_exit_sell1)
```

### NTショート

```text
開始: 日経をBuy1で売り、TOPIXをSell1で買う
終了: 日経をSell1で買い戻し、TOPIXをBuy1で売る
損益 = q_N×M_N×(N_entry_buy1 - N_exit_sell1)
     + q_T×M_T×(T_exit_buy1 - T_entry_sell1)
```

NTの目標・損切りは倍率だけでなく、上式の両脚コスト控除後損益でも検算する。入口時に次を必ず提示する。

- 方向と両脚の売買
- 商品、限月、枚数、乗数
- 各脚の執行側気配と数量
- 各脚名目、グロス名目、名目差率
- 入口`NT_mid`と執行側入口倍率
- 第一・第二目標、損切り、時間撤退
- ファンダメンタルズ前提が崩れる材料撤退

## 9. 実行可能性と数値確信度

次のいずれかなら価格案と枚数案を保留する。

- 同一限月を確認できない、取引最終日を過ぎている、ロール中で比較不能
- 片側板、逆転板、板数量不足、スプレッドが期待幅に対して過大
- 板スナップショットの現在性を確認できない
- 重要指標・中央銀行・SQ・主要構成銘柄イベント直前で、イベント後レンジを推定できない
- OPを主要根拠にしているのにOP有効性ゲートを満たさない

確信度は勝率、期待収益率、価格到達確率ではなく、判断に必要な証拠がどこまで取得・検証・整合したかを表す`証拠充足度`とする。次の20項目を各5点で採点し、未確認・不合格は0点とする。中間点は付けないため、素点は必ず5%刻みになる。

| ブロック | 各5点の確認項目 | 上限 |
|---|---|---:|
| 執行データ | 同一明示限月、両側板、必要数量・スプレッド、セッション状態、回答直前の両脚再取得 | 25 |
| ファンダメンタルズ | マクロ、主要構成銘柄業績、政策、投資主体・信用、業種の広がり、ライブ市場・OPを対象時点付きで確認 | 30 |
| 証拠整合性 | 重複材料を排除、反証を明示、事実・推論・織込み判断を分離 | 15 |
| イベントと期限 | 重要イベントを走査、絶対JST有効期限を計算、期限前・イベント後の再評価条件を指定 | 15 |
| 売買の再現性 | 現在値基準のレンジ算出法、入口・出口・撤退、乗数・枚数・名目差の検算 | 15 |

ファンダメンタルズ6項目は、方向が中立でも、適切な情報源を確認して対象時点と限界を表示できれば各5点を付ける。OPゲート不合格ならOPを使わず、その項目は0点とする。同じ事実を複数項目へ重複計上しない。

```text
確信度素点 = 5点項目の合計
表示確信度 = min(確信度素点, 該当する上限の最小値)
```

次の上限規則を順に適用する。複数該当時は最も低い上限を使う。

| 状態 | 上限 | 必須の判断 |
|---|---:|---|
| 現在板が欠損・失効、または回答直前に再取得できない | 40% | 保留 |
| 同一限月・取引最終日・取引可能性を確認できない | 35% | 保留 |
| 重要イベントの安全余裕内でイベント後分布を評価できない | 50% | 保留 |
| 方向を支持する独立カテゴリが1つだけ | 55% | 見送りまたは保留 |
| 方向を支持する独立カテゴリが2つだけ | 70% | 留意事項へ限定性を明記 |
| 重要な反証が2件以上未解消 | 60% | 見送りまたは保留 |
| 重要イベントの時刻または主要データの鮮度を確認できない | 65% | 留意事項へ欠損を明記 |
| OPを中核根拠にしたがOP有効性ゲートを満たさない | 55% | OP根拠を除外して再判定 |

表示は`60%`のような数値だけとし、定性的な格付け語を併記しない。100%は全チェックを満たしたことだけを意味し、相場結果の確実性を意味しない。採点内訳と適用した上限を第3章または留意事項へ短く示す。
