# 日経225・TOPIX・NTを現在時点から予測する

前日比の説明ではなく、回答直前の同一限月先物板を起点に、その先の方向、相対差、変動時刻、1週間の価格分布を予測する。ファンダメンタルズと需給を別々に分析し、単純方向とNTのどちらにコスト控除後の優位性があるかを比較する。

## 必須資料を読む

分析開始前に次を完全に読む。

1. [references/データ契約.md](references/データ契約.md) — 取得順、公式カレンダー、為替・金利・海外・商品・暗号、Polymarket、J-Quants、OP、鮮度
2. [references/判定と枚数計算.md](references/判定と枚数計算.md) — 3種類の時刻、4象限、生確率と50%超制約、NT相対確率、等価枚数、端数、D1～D5
3. [references/教科書/索引.md](references/教科書/索引.md) — 材料から必要な経済学だけを選ぶ段階読込ルーター

索引を読んだ後、観測した主要材料へ直接対応する教科書だけを通常1～2冊、複合ショックでも最大4冊まで完全に読む。14冊を毎回一括読込しない。追加読込は結論、4象限、D1～D5、または反証が変わり得る場合に限る。使用した教科書名、概念、現在データ、反証の対応を回答へ残す。

回答を組み立てる直前に[assets/回答テンプレート.md](assets/回答テンプレート.md)を完全に読み直し、見出し、表、順序を保つ。

## データ取得と計算を分離する

- 市場データ、ニュース、EDINET DB、政策DB、公開Webの読取専用機能だけを使う。
- 市場データ機能が提供されている場合は最初に`datalist`で契約を確認する。機能自体がない場合は公式Web・利用可能な読取providerへ切り替え、ライブ板が取れなければ具体的な入口・枚数を保留する。未確認のdataset名を推測しない。
- 公式カレンダー、JPX仕様、一次論文は読取専用の検索・ブラウザで確認してよい。
- Polymarketは公開市場・板・価格を分析材料として使う。
- [scripts/index_nt_calculator.py](scripts/index_nt_calculator.py)は取得済みJSONの純計算専用とし、ネット取得へ改造しない。
- [scripts/economic_toolkit.py](scripts/economic_toolkit.py)は索引で選んだ教科書の式が今回の材料へ必要な場合だけ使う。歴史・制度・因果識別を機械計算へ置き換えず、取得機能を追加しない。

## 必須出力を満たす

回答で示す日時は可能な限りJSTへ変換し、すべて`yyyy/MM/dd HH:mm:ss (JST)`で表示する。発表元のIANA timezoneと原UTC offsetは日時と分離して監査欄へ残す。入力データが原timezoneしか持たない場合はJSTへ変換できるまで具体的な時刻判断を保留する。取引日、限月、学習終了日など公式資料が日付だけを定義する項目には架空の時刻を補わず、時刻へ展開する場合は公式に定義された取引終了時刻などの根拠を示す。

回答の章順は、1. 結論と4象限、2. 次の変動候補と有効期限、3. 現在NT倍率・等価枚数・端数方向、4. D1～D5の中心値と変動幅、5. 予測理由、6. OP・需給検証、7. データ鮮度と欠損、8. 無効化条件と再評価、9. 根拠資料とする。独立した「売買設計」章は作らず、入口、二段階出口、価格・時間・材料撤退、脚構成、片脚条件を第1章へ統合する。

### 1. 次の変動時刻と有効期限

次の3つを`yyyy/MM/dd HH:mm:ss (JST)`の絶対時刻で分けて出す。

- `入口板の有効期限`: 現在の提示価格が使える期限
- `次の材料変動候補窓`: 次の実質的な値動きを起こし得る、最も早い重要イベントの開始～終了
- `予測の有効期限`: 4象限と売買方向を再計算すべき期限

これらとは別に、回答を出す実行時のOS実時計を監査する。`as_of`がOS実時計より30秒超未来、120秒超過去、またはOS実時計が入口板・予測の絶対有効期限以後なら、計算値は監査用に残しても`status: hold`とする。入力JSON内の自己申告時刻を実時計の代わりにしない。

変動候補窓には、イベント名、時刻、発生確率または予定確度、影響度、関連性、根拠を付ける。価格が必ず動く時刻とは断定しない。イベントが見つからない場合も、確認範囲と次のモデル再推定時刻を示す。

### 2. 4象限を合計100%で出す

予測の有効期限時点の中値が現在アンカーより上か下かを、次の相互排他的な4象限で示す。

1. 日経買い・TOPIX買い
2. 日経買い・TOPIX売り
3. 日経売り・TOPIX買い
4. 日経売り・TOPIX売り

同じ表に次を出す。

- ファンダメンタルズ単独の4象限分布と主因
- 需給単独の4象限分布と主因
- 生モデル確率
- 四択制約後比較値
- 最大の反証

生モデル確率は合計100.00%にする。四択制約後比較値も合計100.00%にし、一意な最大を必ず50%超、既定では最低50.10%にする。全象限25%の最終回答は禁止する。

ただし、最大50%超を数学的に強制した値は勝率ではない。[references/判定と枚数計算.md](references/判定と枚数計算.md)の射影を使い、「四択制約後比較値」と明記する。生モデル確率は改変せず隣に残す。生モデルが今回と同じ`horizon_seconds`のウォークフォワード検証、象限別件数、損失、確率帯別実現率のゲートを通った場合だけ「期限時点方向の推定的中率相当」と呼べる。取引損益の勝率とは呼ばない。未校正なら「生モデル確率」と呼ぶ。

全base方式に`base_provenance`を持たせ、方式、推定器ID、モデル構造ID、学習打切時刻、今回と同じ期限、原典、モデル成果物SHA-256を固定する。現在のbase予測出力は別の`prediction_output_sha256`で改変検知する。ウォークフォワード校正は同じ方式・推定器・構造・モデル成果物SHA-256へ結び付け、現在予測の動的な平均・分散・重みそのものを校正IDと同一視しない。Polymarket等のシナリオ重みを使う場合、重みの出典と`P(q|s)`を生成した条件付き4象限モデルの来歴・非Polymarket原典を分離して監査する。

自己申告したSHA-256や`validation_passed`だけで情報源・モデル成果物の真正性は保証できない。純計算器の`status: ok`は入力形式、OS実時計に対する現在性、時刻関係、数理不変条件を通過したという意味に限定する。回答には一次資料、対象時刻、モデル来歴、反証を残す。

ファンダメンタルズまたは需給の必須ブロックが空、期限が不一致、現在アンカーが失効している場合は、偽の確率を作らず「算出保留」とする。この場合は50%超値を捏造しない。

### 3. 現在NT倍率と等価枚数を出す

同一限月・近接時刻の中値から現在NT倍率を出し、必ず次を併記する。

- `TOPIX mini 1枚 = 日経225 mini x.x枚`
- `TOPIX mini 1枚 = 日経225 micro x.x枚`
- 未丸めの理論値
- NTを検討する場合は執行側気配による換算値
- mini案とmicro案の整数枚数、各脚名目、名目差率
- 両脚の商品ID、同一四半期限月、取引最終日、個別板時刻・時刻差、入口側板数量
- 取得済み日経板の商品種別と採用商品が一致すること。未取得側のmini／micro候補は理論値と明記

式と整数探索は[references/判定と枚数計算.md](references/判定と枚数計算.md)を使う。小数枚数を実在する契約枚数として示さない。

### 4. NT端数方向を出す

NTロングまたはNTショートを推奨する場合、採用整数枚数について次を省略しない。

- 理論日経枚数と採用枚数の差
- 符号付き残存名目額
- 日経買い超過、日経売り超過、TOPIX買い超過、TOPIX売り超過の別
- 超過脚の生モデル限界確率
- 端数が予測上、有利方向・不利方向・中立のどれか
- 名目差5%ゲート

端数方向が好都合でも、名目差や板数量の制約を破らない。

### 5. D1～D5の1週間パスを出す

J-Quants取引カレンダーで次の5営業日の実日付を決め、日経225とTOPIXを各5行で出す。

- 収束予想中心値（条件付き分布中央値）
- 現在アンカー比
- 68%予測帯
- 90%予測帯
- ファンダメンタルズ寄与bp
- 需給寄与bp
- イベント寄与bp
- 各寄与と`evidence_key`／`event_id`のbp帰属
- 日次ドリフトモデルの版・校正版・学習打切時刻・原典
- 変動幅の算出元
- 当日の主要イベント

日経は有効なOPから増分分散・歪度を得ることを優先し、方向ドリフトをファンダメンタルズと需給から置く。TOPIXはJ-Quantsの同期日足、EWMA・経験分位、日経との縮小相関を基本にする。各日へ累積σではなく前日予測点からの増分σを入力する。非ゼロ方向寄与は検証合格済み`drift_model_provenance`と、合計bpが申告値へ一致するブロック別帰属を必須にする。`major_events`が空の日はイベントドリフトとイベント増分σを0にし、イベントσを使う日は`event_variance_event_ids`へ当日の重要イベントを記録する。非対称累積分位は正の累積σと幅を整合させ、D1からD5へ縮小させない。OPのリスク中立分布を実現確率へ読み替えない。D1～D5を1つの5日終点だけで代用しない。

## 実行手順

### 1. 分析時点と対象を固定する

- 現在日時を日本時間の絶対日時で確定し、現物、日中先物、ナイト先物、休場を区別する。
- 計算直前にOS実時計を再取得し、分析時刻との差、入口板期限、予測期限を現在性ゲートで検証する。
- TOPIX miniと日経225 mini・microの共通して取引可能な四半期限月を選ぶ。`DerivMonth=0`任せにしない。
- 予測アンカーは現在板中値とする。前日終値は、すでに起きた変化と織込みを説明する文脈だけに使う。
- 4象限の評価期限を予測の有効期限と一致させる。

### 2. データを並列取得する

[references/データ契約.md](references/データ契約.md)の順序とゲートに従う。

最初に利用可能な読取能力を確認する。`datalist`があれば契約済みproviderとdatasetを使い、なければ公式Web・利用可能な読取providerへ切り替える。ライブ両脚板の代替がなければ、調査は継続しても具体的な入口・枚数は保留する。

- 実行アンカー: 同一限月両脚板、数量、スプレッド、取引最終日、公式の最終取引可能時刻、現在セッション
- ファンダメンタルズ: ニュース、公式経済カレンダー、リアルタイム為替、JGB・UST、海外株・先物、原油、金、BTC・ETH、主要構成銘柄、政策、地政学、関連するPolymarket
- 需給: 業種の広がり、日経寄与度、先物板・ベーシス、投資部門別、売買内訳、信用、空売り、手口・建玉、OP、SQ・ロール
- 1週間モデル: 同期した日経・TOPIX日足、OP総分散、営業日カレンダー

各市場横断項目は「利用」「不採用」「取得不能」のいずれかを記録し、利用・不採用にはデータ対象時刻を持たせる。利用時は複数の`source_ids`を登録し、各IDを有効倍率が正の証拠、重みが正のシナリオ、シナリオ条件付きモデル、イベント、4象限baseモデル、NT相対価値・相対σ、日次ドリフト、営業日または変動幅へ実際に結び付ける。品質0の証拠や重み0のシナリオを消費先に数えない。Polymarketだけは関連市場がなければ「非該当」を許す。取得不能を中立材料とみなさない。リアルタイムFX、経済カレンダー、海外市場を含むcoverage分析ゲートが未達なら保留する。

### 3. 証拠台帳を作る

各材料に一意な`evidence_key`を付け、次を記録する。

- ファンダメンタルズまたは需給の所属
- 事実、推論、織込み判断
- 日経・TOPIX・4象限への作用
- 反証
- データ対象時点、取得時刻、半減期、品質
- 同一事象とまとめた別ソース
- 対応する`coverage_item`と`source_id`。coverageが`used`でない情報源を証拠へ使わない。12項目外の固有DB等は`other`とし、対象時刻・確認時刻・鮮度上限を`other_sources`へ登録する

同じイベントをニュース、EDINET、政策DB、Polymarket、クロスアセットで重複加点しない。

必要な経済式がある場合は、教科書索引で適用条件と限界を確認してから`economic_toolkit.py`で検算する。計算名、入力値・単位・対象時点、採用した仮定、感度または反証を証拠台帳へ残す。教科書の比較静学だけから日経・TOPIXの符号を決めない。

### 4. 次の変動候補窓と期限を計算する

D5までのイベント候補を走査し、[references/判定と枚数計算.md](references/判定と枚数計算.md)のmateriality式で順位付けする。閾値は0.35へ固定し、予定済みイベントの発生確度は1とする。原時刻のUTC offsetをIANAタイムゾーンの当日規則と照合し、最も早い重要窓、安全余裕、入口板期限、モデル再推定時刻を別々に計算する。予測期限はイベント探索上限のD5を越えさせない。D1～D5内の全重要イベントIDを最初の対象予測点へ必ず結び付ける。

### 5. 純計算ツールで検算する

取得・推論結果をJSONへ正規化し、実行環境がある場合は次を必ず実行する。

初回または入力項目が不明な場合だけ[assets/計算入力例.json](assets/計算入力例.json)を読み、架空値を全て取得済み実データへ置換する。実入力では`sample_only: false`を明示し、`_sample_notice`だけを削除する。合成model、商品ID、URI、情報源が残れば計算器が拒否する。入力例のままなら出力は`sample_only`となり、実分析の数値として扱わない。

```powershell
python .agents/skills/pnd-forecast-japan-index-nt/scripts/index_nt_calculator.py `
  --input <入力JSON> `
  --pretty
```

スクリプト出力の合計、最大値、端数符号、D1～D5を回答へ転記する。失効板、期限不一致、異限月、非同期板、アンカー不一致、必須データ確認漏れのエラー時は再取得または入力修正を行い、数値を手で穴埋めしない。実行環境がない場合は同じ式を再現し、未検算と明記する。

### 6. 戦略を選ぶ

- 両指数が同方向で、生モデル確率、ファンダメンタルズ、需給、広がり、コスト控除後余地が整合する場合は単純ロングまたはショートを優先候補にする。
- 共通方向が弱く、相対ドリフト、構成業種、為替、金利、主要構成銘柄、先物・OP需給からコスト控除後の差がある場合はNTを候補にする。
- NTロングは日経買い・TOPIX売り、NTショートは日経売り・TOPIX買いとする。
- NT判断は4象限首位だけで決めず、`P(日経リターン-TOPIXリターン > 往復コスト)`または逆方向を別計算する。
- 生モデルとNT相対価値がコスト帯内、重要イベント直前、板不良、期限一致ウォークフォワード校正不能、反証未解消なら見送る。
- `nt.strategy`を指定する場合は採用整数枚数を必須とし、採用方向の相対ドリフトが往復コストを超え、かつ採用方向確率が逆方向・コスト帯内の両方より高い場合だけ候補にする。
- `local_position_gate_passed`はコスト、名目差、流動性、相対価値だけの局所判定とする。最終推奨には`status: ok`と`local_position_gate_passed: true`の両方を必要とし、期限やcoverage等の全体保留を局所判定で上書きしない。
- NT相対ドリフト3成分は有効なファンダ・需給証拠または重要イベントへbp単位で帰属させ、合計を申告値と一致させる。イベント帰属は分析時刻より後かつ4象限・NT評価期限以前に限定し、期限後イベントへの先回り効果は現在観測済みのファンダまたは需給証拠として扱う。相対σの原典と期限一致の`model_provenance`を別に残し、未検証モデルならNTを採用しない。
- 申告往復コストは現在の両脚bid・askから計算する観測最低コスト以上とする。4象限の予測有効期限とD5は、NT推奨の有無にかかわらず共通限月の公式最終取引可能時刻を越えない。
- 四択制約後比較値だけを根拠に売買しない。

### 7. 入口・出口・撤退を作る

- ロングは`Sell1`、ショートは`Buy1`を入口にする。
- NTは両脚の正しい執行側気配を使う。
- 第一・第二目標、価格撤退、予測有効期限による時間撤退、材料撤退、イベント後の再評価を出す。
- NTは倍率だけでなく、両脚コスト控除後損益でも出口と撤退を検算する。
- 証拠金・口座資産・許容損失が未指定なら、名目差条件を満たす最小構成を例示し、口座に適した枚数とは断定しない。

### 8. 回答直前に再取得する

- 先物両脚を近接時刻に再取得する。
- アンカー、NT倍率、等価枚数、整数構成、端数、入口、出口を再計算する。
- 重要イベント予定、為替、海外先物が分析中に変化していないか確認する。
- テンプレートを完全に読み直してから回答する。

## OPを使う条件

- 実登録限月、取引最終日、SQ、登録基準価格・範囲、現在先物との位置を毎回確認する。
- ATMと上下複数ストライクのCall・Put両側板を検証する。
- `CurrentPrice=null`だけで板なしと判定しない。板時刻と最終約定時刻を分ける。
- 生のIVを現在板から逆算したIVと呼ばない。
- 裁定条件を満たすOP面からだけ分散・歪度・リスク中立密度を作る。
